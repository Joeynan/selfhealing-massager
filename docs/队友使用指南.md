# 队友使用指南

适用：macOS Apple Silicon、Windows x64；继续使用现在这台 SenseCAP Watcher（小智）和黑色 ESP-12F / NodeMCU 板。先看本指南完成软件与网络，再接入舵机。仓库中的配置示例不包含真实密码或当前设备地址。

## 1. 各部分做什么

| 部分 | 作用 | 主要源码 |
|---|---|---|
| 小智 ESP32-S3 | 采集画面、Wi-Fi 服务、状态与动画、长按电源、滚轮切页、向黑板转发动作 | `work/xiaozhi-esp32/main/boards/sensecap-watcher-gesture` |
| 小智视觉芯片 | 沿用设备现有摄像头采集固件 | 本次不重新烧录，不移植板上模型 |
| 电脑识别 | 取得小智图像，用 MediaPipe 提取最多两只手的 21 节点，按规则确认手势 | `outputs/Watcher控制台/camera` |
| 电脑控制台 | 浏览器界面、模拟、校准、设备状态与日志 | `outputs/Watcher控制台` 的 `server.py`、`bridge.py` 和网页文件 |
| 黑色 ESP8266 板 | 接收 Watcher 的 SET2 指令，设置三路舵机脉宽并回执；保存校准与配对 | `outputs/Watcher控制台/firmware/esp8266/watcher_controller` |

链路是“小智摄像头 → Wi-Fi → 电脑识别 → 小智 → Wi-Fi → 黑板 → 舵机”。电脑 USB 不是运行必需条件，但电脑识别服务仍必需。网页“板上识别”项用于研究诊断，当前未验证的板上模型不能代替电脑识别。现在暂不使用 Uno 或 SoftwareSerial。

## 2. 要准备什么

- 现有小智与黑色 ESP-12F 板；两块板各用可靠的数据线进行配置、烧录。
- 电脑与设备处于可互相访问的 Wi-Fi 网络。ESP8266 需 2.4GHz；同一个 Wi-Fi 名称不保证设备可互通，访客网络／客户端隔离可能阻断通信。
- 三路当前使用的 9g 连续旋转舵机、独立稳压 5V 电源（现有方案为 5V/3A）及共地线。
- Git、Python 3.12。仅运行网页和识别不需要安装 ESP-IDF 或 Arduino IDE；需要开发／烧录相应板时再安装。

| 黑板连接 | 接法 |
|---|---|
| D1 / GPIO5 | 捶打组舵机信号 |
| D2 / GPIO4 | 揉搓组舵机信号 |
| D3 / GPIO0 | 轻捏组舵机信号 |
| 舵机正极 | 独立 5V 电源正极 |
| 舵机负极 | 独立电源 GND；同时与黑板 GND 共地 |

外部 5V 不接入黑板 3V3；舵机电源不取黑板 3V3。D3 是启动相关 GPIO0，若上传／启动失败，先断电并检查外围是否拉低该脚。首次操作和烧录时舵机断电；固件与摄像头验证完成后再接通独立 5V，观察运动。

2000µs 为当前运行设置、1500µs 为中立，频率 50Hz；这套设置对应当前按连续旋转使用的实物，不代表所有标 SG90 的型号都适用。这里只显示提交脉宽，不显示未经测量的转速、电流或机械停转结果。

在工程根目录执行：

macOS：

```zsh
./安装摄像头依赖.command --with-flash
```

Windows PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File .\安装摄像头依赖.ps1 --with-flash
```

第一次确保 `python3.12`（Mac）或 `py -3.12`（Windows）可用。安装器创建 `work/watcher-control-runtime/venv`，并准备固定模型；`--with-flash` 同时准备 esptool 环境。仅准备烧录工具可用 `--flash-only`；校验现有安装可用 `--check`，不会改 Wi-Fi 或烧录。

有已准备的本平台依赖包和已校验模型时，可用 `--offline --wheel-dir "本地依赖包目录"`；没有模型的首次安装需要下载，离线安装不能凭空补齐。需要重建 Python 环境时使用根目录 `重建运行环境.command`／`.ps1`，该入口不重建 ESP-IDF。

安装只创建本机运行目录及不存在的配置，保留已有设备地址与校准。模型与环境不提交到 GitHub。前端由 Python 提供，不需要 `npm install`。

## 4. 小智烧录：直接使用发布版

这条路线不用编译整套源码。取得 Release 附件 `selfhealing-watcher-v9.zip`，先核对 [发布索引](../releases/release-index.json) 的 ZIP 校验值，再解压到工程 `work/releases/watcher-v9`。解压后应直接看到 `release-manifest.json` 和 `watcher-controller-v9-wheel-face.bin`，回滚文件位于 `上一版回滚`。

发布索引暂未填写远程下载 URL 时，表示附件尚未发布；由维护者上传至本私有仓库后提供 Release 链接，不把文件名当作已经上传。

1. 断开独立 5V 舵机电源；小智 USB 保留，关闭占用串口的监视器。
2. 先运行下列离线检查；它不枚举、打开或写入设备。
3. 实际烧录时明确选择控制串口，写入及校验成功后，在舵机断电状态确认网页、画面和显示。

macOS：

```zsh
./烧录小智.command --release-dir "work/releases/watcher-v9" --dry-run
./回滚小智.command --release-dir "work/releases/watcher-v9" --dry-run
```

Windows PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File .\烧录小智.ps1 --release-dir "work/releases/watcher-v9" --dry-run
powershell -ExecutionPolicy Bypass -File .\回滚小智.ps1 --release-dir "work/releases/watcher-v9" --dry-run
```

离线检查通过后，实际写入将 `--dry-run` 改成 `--port "控制串口"`。示例：Mac 为 `--port "/dev/cu.usbmodemXXXXXXXX703"`，Windows 为 `--port COM7`。这些是格式示例，需选本机实际控制串口；Windows 实际写入必须显式填写 COM 口。回滚用对应回滚入口，不手工拼接擦除／全片写入命令。

当前发布版只允许这台设备：ESP32-S3、MAC `10:b4:1d:e6:00:9c`，应用地址 `0x200000`，镜像按 4MiB 构建上限检查；入口还读回实际分区与启动选择，仅接受已核验的 4MiB 或 12MiB `ota_0` 布局，且当前启动为 `ota_0`。不要通过修改 MAC 或地址绕过检查。别的 Watcher 必须先核验硬件及分区，由维护者准备对应的发布清单。

小智 CH342 桥会出现两个端口。现有 Mac 上控制接口末尾为 `...703`，`...701` 是视觉接口；Windows 的 COM 编号由系统分配，需选控制接口。入口仍检查芯片和身份，不能仅凭 COM 数字认板。烧录不使用全片擦除，不改 NVS、Wi-Fi、校准、bootloader 或视觉芯片。

保留的 v9 发布清单标记的是原发布时状态，不修改原文件来补写本次交付结论。附件和离线检查通过不等于队友设备已经烧录；队友实际写入、读回及现场机械测试另行验收。

## 5. 修改小智源码和构建

只有需要开发固件时才走这条路线。先按本项目入口准备固定 ESP-IDF；安装程序核对版本／提交，并对锁定组件应用摄像头补丁。补丁可重复识别，遇到未知组件版本应停止检查，不手工跳过。各电脑使用自己平台的编译器。

本次不提供复制自 Mac 的 SDK 工具包。安装 Git，并取得固定 SDK 源码：

```text
git clone --recursive --branch v6.0.1 https://github.com/espressif/esp-idf.git work/esp-idf
git -C work/esp-idf rev-parse HEAD
```

确认输出为 `8c19b156084a0753687347cca1f5355782893533`。已有别的 SDK 不覆盖它，另准备该固定版本。安装、激活平台工具：

macOS：

```zsh
./work/esp-idf/install.sh esp32s3
source ./work/esp-idf/export.sh
./构建小智固件.command --clean --jobs 6 --idf-path "work/esp-idf"
```

Windows：安装器需可用的 Git、Python 和构建基础工具。可按官方 ESP-IDF 6.0.1 安装流程准备它们；对刚取得的固定 SDK，在 PowerShell 执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\work\esp-idf\install.ps1 esp32s3
. .\work\esp-idf\export.ps1
powershell -ExecutionPolicy Bypass -File .\构建小智固件.ps1 --clean --jobs 6 --idf-path "work/esp-idf"
```

若 SDK 安装在别处，把 `--idf-path` 换成该目录。构建入口不下载最新 SDK；未激活工具环境、提交／锁／补丁内容不符时会停止。构建报告写入 `work/xiaozhi-esp32/build/selfhealing-build-report.json`。

构建结果位于 `work/xiaozhi-esp32/build/xiaozhi.bin`。构建程序检查 ESP32-S3、专用板型、分区、镜像大小；成功只说明构建通过，**不会自动替换 v9 Release 包**。若要烧录自行修改的应用，维护者需创建新版本发布清单及 SHA256，继续使用同样的身份／地址检查和回滚流程，不将新文件覆盖到旧清单来骗过校验。

SDK 安装的官方背景资料：[ESP-IDF 6.0.1 Windows 安装](https://docs.espressif.com/projects/esp-idf/en/v6.0.1/esp32s3/get-started/windows-setup.html)。本工程固定 6.0.1，不能直接采用文档中的最新版本替换。

## 6. 黑板烧录与库

黑色板当前 v7 与小智 v9 的 `hold_protocol=2` 兼容。只改小智表情或网页时不必重烧黑板；修改黑板 Wi-Fi 或接收逻辑时再编译上传。

1. 安装 Arduino IDE 2。在“首选项 → 附加开发板管理器网址”添加：

   ```text
   https://arduino.esp8266.com/stable/package_esp8266com_index.json
   ```

2. 在开发板管理器安装 **esp8266 by ESP8266 Community 3.1.2**；选择 **NodeMCU 1.0 (ESP-12E Module)**。CLI 等价板型为 `esp8266:esp8266:nodemcuv2`。
3. 打开 `outputs/Watcher控制台/firmware/esp8266/watcher_controller/watcher_controller.ino`。该文件夹中其余 `.h` 要一起保留，不单独复制 `.ino`。
4. 把 `wifi_settings.example.h` 复制成本地私有 `wifi_settings.h`，填自己的值：

   ```cpp
   #pragma once
   constexpr const char* WIFI_SSID = "YOUR_WIFI_NAME";
   constexpr const char* WIFI_PASSWORD = "YOUR_WIFI_PASSWORD";
   ```

5. 库 `ESP8266WiFi`、`ESP8266mDNS`、`ESP8266WebServer`、`EEPROM`、`Servo` 均随 ESP8266 Core 提供，无需另装 Uno 的 SoftwareSerial 或改用 ESP32 Core。
6. 断开舵机电源，连接黑板 Micro-USB，选正确串口，先“验证”，再“上传”；首次可用 115200 上传速率。保留既有 Flash／EEPROM 设置，不选擦除全部 Flash。上传后打开串口监视器 115200 查看联网与身份回报。
7. 新会话需要正确 Watcher 身份、PROFILE 同步与 ARM 才启用。EEPROM 保存目标、校准和配网页密码，但不保存已启用状态；Watcher 的默认启用偏好在就绪后发送新的启用请求。

黑板生成的 `.bin` 会包含填写的 Wi-Fi 信息，不提交源码仓库、不作为共享 Release 附件。配网页 `CONFIG_AUTH` 密码、EEPROM 备份和串口完整日志也留本机。Core 安装背景见 [ESP8266 官方安装说明](https://arduino-esp8266.readthedocs.io/en/stable/installing.html)。

## 7. Wi-Fi、密码与 IP 怎么改

### 7.1 小智 Wi-Fi：保存配置，不重新编译

舵机断电后，将小智控制串口接电脑，关闭烧录工具，在 Arduino IDE 或其他串口终端选择 115200，发送：

```text
lan_wifi "YOUR WIFI NAME" "YOUR_WIFI_PASSWORD"
```

SSID 有空格时必须带双引号。命令接受 SSID 1–32 字节、密码 8–63 字节；得到 `LAN_WIFI_SAVED; reboot to connect` 后重启小智。可使用关机／开机，USB 供电时需确保真正重启，而不只是进入软件待机；也可断开 USB 和按电源操作。`lan_status` 输出当前通信状态，不输出明文密码。

这是固件串口命令，不是在电脑终端里作为系统命令执行。终端可能显示输入回显，别把带真实密码的截图或日志上传。新长按规则不会擦除网络配置。

### 7.2 黑板 Wi-Fi：本地修改并重新上传

修改私有 `wifi_settings.h` 的 `WIFI_SSID` 和 `WIFI_PASSWORD`，重新编译并上传黑板，重启后确认 `WIFI_JOINED ip=...`。这两个字段是黑板连接路由器的 Wi-Fi，目标小智 IP 另由配对流程保存。

### 7.3 小智 IP 改变

转动小智滚轮到数据页读取 IP。把控制台的 Watcher URL 更新成 `http://小智IP:8080`；启动参数可覆盖本机配置：

macOS：

```zsh
./启动控制台.command --watcher-url http://WATCHER_IP:8080
```

Windows PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File .\启动控制台.ps1 --watcher-url http://WATCHER_IP:8080
```

把 `WATCHER_IP` 替换为实体屏显示的地址。`--watcher-url` 只覆盖本次启动；长期保存时修改私有 `outputs/Watcher控制台/settings.json` 中的 `watcher_url`。安装器只在该文件不存在时从 `settings.example.json` 创建；示例地址 `192.0.2.1` 需换成真实小智 IP。`camera_url` 保持本机识别服务 `http://127.0.0.1:8877`。

只看离线页面且不访问设备：

```text
python outputs/Watcher控制台/launch.py --offline --no-browser --dashboard-port 8895
```

也可给上述系统入口加相同三个参数。浏览器打开 `http://127.0.0.1:8895/`；正常控制台 8890 可以同时保留。

电脑与黑板都连接小智。**黑板目标是小智 IP，不是电脑 IP**；电脑识别服务 8877 也不填入黑板目标。只有电脑网卡地址改变而小智 IP 没变，通常不用改小智或黑板。

黑板尝试 mDNS 发现 `_watcher-servo._tcp` 的 8888 服务，并核对保存的 Watcher 设备 ID。网络禁用 mDNS 或小智换 IP 后未自动恢复时，用同一网络手机访问 `http://黑板IP/`：用户名 `admin`，Digest 密码从黑板本地 USB 启动行 `CONFIG_AUTH` 取得。填小智数据页的 IP；首次配对可留空设备 ID让握手登记，已有 ID 保留身份检查。

打开已认证的黑板配网页会先禁用、脱离舵机输出，保存后不在黑板单独自动启用。返回控制台等待新的会话、配置、中立确认及新输入；曾手动禁用时再手动恢复。不要改 ID来连接不明设备。

### 7.4 地址和端口对照

| 所在设备 | 地址示例 | 用途 |
|---|---|---|
| 电脑 | `http://127.0.0.1:8890/` | 队友在本电脑浏览器打开控制台 |
| 电脑 | `http://127.0.0.1:8877/status` | 识别服务状态，启动器使用 |
| 小智 | `http://WATCHER_IP:8080/status` | 小智控制与状态服务 |
| 小智 | `http://WATCHER_IP:8081/frame` | 摄像头图像，电脑经 Wi-Fi 读取 |
| 小智 | `WATCHER_IP:8888` / TCP | 黑板主动连接的小智控制服务 |
| 黑板 | `http://BLACK_BOARD_IP/` / 80 | 身份认证后的手机配网页 |

`127.0.0.1` 是打开程序的这台电脑，不是小智。设备与电脑可以处于不同网段，但路由和防火墙必须允许以上连接；无须为了运行把控制台对外网开放。

## 8. 网页怎么用

启动成功后浏览器打开 `http://127.0.0.1:8890/`。保留启动窗口；Ctrl+C 结束该窗口启动的会话。启动器只复用已核验属于当前工程的服务，不会结束其他工程进程；端口被未知程序占用时按报错回到原窗口处理。

1. **设备状态：**先看小智和黑板在线、固件、配置一致、回执新鲜。显示在线只说明连接可读，不代表输出已启用或舵机运动。
2. **摄像头诊断：**选“Mac 摄像头诊断”，看 Wi-Fi 画面、手节点、实时姿态与顶部已确认手势。稳定静态手势要求至少三个不同帧且保持 300ms；揉搓包含动态开合与四指收拢、拇指明显伸出的静态变体。双手冲突不执行。
3. **表情与保持：**确认后网页与实体圆屏同步；同手势新确认刷新 5 秒，新手势立即切换。普通未识别不刷新期限；无手超过 800ms 停止运动。摄像头新鲜画面时实体灯低亮度绿色，停止或过期时熄灭。
4. **输出：**持续默认启用的偏好仍受设备就绪守卫约束。停止按钮请求三路中立并保留启用偏好，新确认可再运动；“禁用输出”暂停动作，手动启用恢复。正在等待连接／中立／配置时，先解决提示，别重复点击。
5. **模拟：**先停止当前动作，选“模拟手势”；模拟来源不会被摄像头识别覆盖。选捶打／揉搓／轻捏测试 2 秒后回中立；有输出时观察实体运动，禁用输出时只验证表情与通信。
6. **单路校准：**只在模拟诊断下使用。通道 D1/D2/D3、脉宽 1000–2000µs、时长 100–500ms；“填入运行值”使用当前保存值。短测结束回中立，不要求每次重复启用；按钮灰色时阅读旁边条件提示。
7. **保存校准：**修改三路中立／运行值后保存，等待两板配置一致。当前默认 1500／2000，已有自定义值不应被随意覆盖。
8. **观察与日志：**短测后点“已转动／已停止／无响应／异常”记录本次实物结果。日志包含识别、保持、切换、指令、回执、三路脉宽、租约及停止原因；“导出日志”下载 JSON。公开前检查设备地址及私人内容。

## 9. 小智实体屏与电源

| 操作 | 结果 |
|---|---|
| 电池关机时长按滚轮约 3 秒 | 开机；首次松手只解除开机保护 |
| 运行时按满 3 秒并松手 | 请求中立、禁止新动作；电池供电关机，USB 供电软件待机 |
| USB 待机时长按 3 秒并松手 | 恢复摄像头，等待新的会话、中立确认与识别 |
| 短按 | 无动作 |
| 滚轮顺时针一个卡位 | 进入数据页，查看 IP、黑板、摄像头、手势、脉宽和电量 |
| 滚轮逆时针 | 返回整屏黑底大表情页；页面端点不循环 |

数据页显示“黑色板未连接”时先查网络；就绪时显示“舵机可控制”。断线后的脉宽标注“上次回报”，不是当前输出。看数据页不暂停识别，返回表情页显示最新有效表情。

## 10. 常见问题

| 现象 | 先查什么 |
|---|---|
| 两板都在线但舵机按钮灰色 | 当前来源是否模拟、输出是否被手动禁用、配置一致和中立回执是否完成；看按钮提示，不只看在线标签 |
| 短测一次后又禁用 | 核对小智为 v9、黑板 hold_protocol=2；先看停止原因、回执是否过期；旧版短测行为不同 |
| 没画面／绿灯不亮 | 小智是否运行而非 USB 待机；小智 IP、8081 可达、识别服务是否正常；电脑仍须开着 |
| 画面有但识别未就绪 | 模型 SHA、Python 3.12、固定 MediaPipe 与依赖、识别窗口错误；手是否清晰完整，画面是否过期 |
| 网页识别了但表情不更新 | 顶部已确认还是下方瞬时姿态；摄像头来源是否选对；帧是否新鲜、设备是否收到确认；不要拿旧结果续期 |
| 小智在线、黑板未连接 | 黑板供电与 Wi-Fi、目标 IP及设备 ID、TCP 8888、mDNS；必要时用黑板配网页 |
| 同 Wi-Fi 仍无法连接 | 客户端隔离／访客网、路由、防火墙、休眠、地址变化；跨网段不一定可达 |
| 串口打不开／烧录失败 | 监视器占用、USB 数据线、端口选择；Watcher 使用控制端口，不选视觉端口；身份／分区失败不要绕过 |
| 黑板启动失败／D3 异常 | GPIO0 是否被外设拉低、供电与接线；舵机断电后再排查启动 |
| 舵机无响应，但有 APPLIED | 回执只证明软件提交；查独立 5V、共地、信号线、实际通道、校准中立；断电后交换通道区分线束与输出问题 |
| 舵机停转不稳定 | 检查每路实物中立点与供电，不把软件 1500µs 等同所有舵机已机械停转 |
| 8890／8877 被占用 | 回原启动窗口 Ctrl+C；未知进程不能直接结束；离线预览可选未占用端口 |
| Windows 首次无法下载依赖 | 检查 Python 3.12 x64、网络及官方源，使用平台对应 wheel；不复制 Mac 的 venv |

## 11. 修改与分享

后续只修改活动 Watcher 源码及当前控制台，不手工维护历史发布快照。提交前运行白名单审计与回归测试；具体见 [GitHub 上传指南](GitHub上传指南.md)。新硬件、网络或参数需按 [验收清单](队友验收清单.md) 记录，构建通过、软件回执、现场运动分开写。
