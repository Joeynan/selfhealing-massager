# 源码提交清单

准确文件名、大小和 SHA256 由导出目录根的 `source-manifest.json` 列出；该清单不把自己递归计入校验。可提交范围由 `tools/package_team.py` 定义，导出后再运行 `audit --staged` 检查实际 Git 暂存内容。

| 保留范围 | 内容 |
|---|---|
| 根目录 | README、工程约定、忽略规则、Mac／Windows 标准入口 |
| `work/xiaozhi-esp32` | 当前 Watcher 与上游基线源码、版权文件、固定组件锁；生成文件除外 |
| `outputs/Watcher控制台` | 网页、服务、识别规则、示例设置、模型下载清单、运行／烧录依赖锁、测试 |
| 黑板源码 | 当前 `.ino` 与配套头文件、Wi-Fi 配置示例；唯一允许提交的 `wifi_settings.h` 是固定路径的合成测试桩 |
| Watcher 控制源码与视觉消息测试 | 当前控制／显示源码和必要主机测试支持，不加入新视觉烧录操作 |
| `tools` | 安装、构建、受保护烧录／回滚、导出、测试与固定补丁和配置 |
| `docs` | 使用指南、GitHub 上传、第三方许可、验收清单与本次交付验证 |
| `.github/workflows` | Windows 软件自动验证流程 |
| `releases/release-index.json` | 原 v9／v8 附件版本及校验索引，不是镜像本身 |

不提交：完整 SDK、编译器、Python 环境、wheels、managed_components、build／缓存、历史实验、私人图像与日志、实际 settings.json、Wi-Fi 私有头文件、NVS／EEPROM／全片设备备份及含私有网络信息的两板构建镜像。固定公开手模型首次安装时下载，不放入源码。

原 v9／v8 应用单独放入 `selfhealing-watcher-v9.zip`，作为 Release 附件；对应校验值保持不变。黑板应用及开启源码配网的小智应用由使用者用自己的私有网络设置在本机构建，不分发含密码的应用。

本机 `work/team-delivery/source` 是导出快照；后续活动源码仍只维护当前完整工程。上传及更新步骤见 [GitHub 上传指南](../GitHub上传指南.md)。
